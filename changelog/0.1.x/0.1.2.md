# 0.1.2 — 2026-10-02

## Added

- **`oeis_get_sequence` `fromItem`** pages a `sections` selection past the 100,000-byte response budget: the response is cut between whole items and `nextFromItem` names where to resume; a `fromItem` outside `sections` fails as `from_item_not_selected` ([#7](https://github.com/cyanheads/oeis-mcp-server/issues/7)).
- **`author`, `modified`, and `legacyIds`** on `oeis_search_sequences`, `oeis_identify_sequence`, and `oeis_get_cross_refs` rows, in `oeis_get_sequence`'s formats (`modified` is ISO 8601 with offset); each is absent where OEIS has none ([#8](https://github.com/cyanheads/oeis-mcp-server/issues/8)).
- **Hosted endpoint** `https://oeis.caseyjhand.com/mcp`, listed in `server.json` `remotes` and the README; its callers share one oeis.org pace.

## Changed

- **`oeis_identify_sequence`** names the data-line limit in its description, and in its zero-hit notice when the run likely lies past every data line: OEIS matches a run only within each entry's data line (at most about 270 characters), never its b-file ([#9](https://github.com/cyanheads/oeis-mcp-server/issues/9)). `oeis_list_reference` topic `identifiers` says the same.
- **`oeis_search_sequences`** adds that zero-hit sentence, on the same conditions, to a query OEIS reads as one `seq:` or `signed:` run of terms ([#10](https://github.com/cyanheads/oeis-mcp-server/issues/10)).
- **Linear-time tests** bound thread CPU time instead of wall-clock time.

## Fixed

- **`oeis_get_terms`** reaches b-file terms past the first 1 MiB, reading later 1 MiB parts by byte range pinned to the file's ETag, at most two part reads a call; `bFileCut` now means the file continues past `lastAvailableIndex` ([#6](https://github.com/cyanheads/oeis-mcp-server/issues/6)). A b-file served without byte ranges or a strong ETag is still read only to its first 1 MiB.
- **Record cache**: a freshly fetched search row showing a later edit expires the cached record, which the next read revalidates, and a row listing an A-number drops its remembered `404` ([#11](https://github.com/cyanheads/oeis-mcp-server/issues/11)).

## Dependencies

- `@modelcontextprotocol/server` ^2.1.0 → ^2.2.0 (dev dependency). The lockfile's single installed copy, which `@cyanheads/mcp-ts-core` also resolves to, is now 2.2.0, so the Docker image and the `.mcpb` bundle run SDK 2.2.0.
