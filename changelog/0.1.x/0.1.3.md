# 0.1.3 — 2026-10-18

## Changed

- **`oeis_get_terms` `limit`** accepts any positive integer and is served at 1000 when larger: `cap` is the applied value, and a slice the 1000-term cap ended says `Stopped after 1000 terms, the most one call returns (limit was N); call again with fromIndex k.` ([#17](https://github.com/cyanheads/oeis-mcp-server/issues/17)).
- **`oeis_search_sequences`** adds a notice when `effectiveQuery` shows OEIS split the numbers into separate searches, with the comma-joined run to send instead; on a zero-hit it replaces the drop-first and `subseq:` advice. The `query` description and `oeis_list_reference` topic `search_syntax` say the same ([#13](https://github.com/cyanheads/oeis-mcp-server/issues/13)).
- **Framework sync** to `@cyanheads/mcp-ts-core` 0.13.15: skills, scripts, `Dockerfile` (bun 1.4.3, musl packages pruned), `.dockerignore`, `.env.example`, CodeQL (one analysis per language), and `server.json` (`runtimeHint` `npx`, no `packageArguments`).

## Fixed

- **`oeis_get_terms`** drops a cached no-b-file answer when a fetched or revalidated record lists a b-file, and asks for the b-file again in the same call ([#12](https://github.com/cyanheads/oeis-mcp-server/issues/12)).
- **`oeis_get_terms`** skips malformed b-file lines and counts them in the `notice` with the b-file URL; a b-file read whole with no `n a(n)` pair fails as `upstream_unparseable` and is not cached ([#16](https://github.com/cyanheads/oeis-mcp-server/issues/16)).
- **`content[]`** renders contributor text as code spans and code fences, so markdown clients show formulas, names, and the line and paragraph separators as written; `structuredContent` is unchanged ([#15](https://github.com/cyanheads/oeis-mcp-server/issues/15)).
- **`oeis_search_sequences`** gives a zero-hit `_` wildcard run the term-run advice instead of "Loosen the query" ([#18](https://github.com/cyanheads/oeis-mcp-server/issues/18)).
